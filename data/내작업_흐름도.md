# 내가 하는 일 — 전체 흐름

비개발자용. 용어는 처음 나올 때 괄호로 풀어 씁니다.

---

## 0. 한 줄로 말하면

**AI가 소명서를 쓸 때 참고할 "자료집"을 만드는 일**입니다.

AI(정확히는 LLM — 글을 만들어 내는 인공지능)는 아는 게 많아 보이지만, **우리가 모은 실제 사기 사례는 하나도 모릅니다.** 그냥 시키면 그럴듯한 거짓말을 지어냅니다. 그래서 답을 만들기 직전에 **"이 사람 상황은 이런 유형이고, 비슷한 실제 사례는 이랬다"는 자료를 손에 쥐여 줘야** 합니다.

그 자료집을 만들고, 상황에 맞는 자료를 골라 주는 장치를 만드는 게 제 일입니다.

---

## 1. 용어 먼저

| 말 | 뜻 |
|---|---|
| **DB** (데이터베이스) | 자료를 넣어 두는 창고. 엑셀 파일 여러 개가 들어 있는 폴더라고 생각하면 됩니다 |
| **테이블** | 그 창고 안의 표 하나. 엑셀의 시트 한 장 |
| **행 / 열** | 표의 가로줄 하나 / 세로칸 하나 |
| **스키마** | 표를 어떤 모양으로 만들지 정한 설계도. "이 표엔 이런 칸이 있다" |
| **SQL** | DB에 말을 거는 언어. "이 표에서 이거 꺼내 줘"를 쓰는 방법 |
| **시드**(seed) | 처음에 넣어 두는 기본 자료. 씨앗이라는 뜻 |
| **쿼리** | DB에 던지는 질문 한 개 |
| **LLM** | 글을 만들어 내는 AI. ChatGPT, Claude 같은 것 |
| **프롬프트** | LLM에게 주는 지시문. "이 자료를 보고 이렇게 써 줘"라고 적은 글 |
| **RAG** | 답을 만들기 전에 **관련 자료를 먼저 찾아서 같이 넣어 주는 방식**. AI가 지어내지 않게 하는 방법. 보통은 뜻이 비슷한 글을 검색해서 찾지만, **우리는 유형이 16개뿐이라 검색 없이 유형 번호로 꺼냅니다** |
| **임베딩** | 글을 숫자 덩어리로 바꿔서 "뜻이 비슷한 글"을 찾을 수 있게 하는 기술 |
| **토큰** | AI가 글을 세는 단위. 대충 한글 한 글자가 1~2토큰 |
| **캐시** | 한 번 계산한 걸 저장해 뒀다가 다시 쓰는 것. 돈과 시간이 절약됨 |
| **API** | 프로그램끼리 대화하는 창구. 화면(앱)이 서버에 "이거 줘"라고 요청하는 통로 |
| **JSON** | 자료를 주고받을 때 쓰는 글자 형식. `{"이름": "값"}` 모양 |
| **SSH** | 멀리 있는 컴퓨터(서버)에 접속하는 방법 |
| **psql** | DB에 직접 말을 거는 프로그램 |
| **프론트 / 백엔드** | 사용자가 보는 화면 쪽 / 뒤에서 계산하는 서버 쪽 |

## 2. 전체 그림

```
 ┌── 내가 미리 만들어 두는 것 (지금 하는 일) ────────────────┐
 │                                                           │
 │  ① 실제 사례 모으기        →  corpus_documents 표        │
 │  ② 사례마다 유형 붙이기    →  T1~T16 중 하나              │
 │  ③ 중요한 부분만 요약      →  case_digests 표            │
 │  ④ 유형별로 한 덩어리로 합치기 → snippet_packs 표         │
 │                                                           │
 └───────────────────────────────────────────────────────────┘
                              ↓ (미리 만들어 둠)
 ┌── 사용자가 서비스를 쓸 때 벌어지는 일 ────────────────────┐
 │                                                           │
 │  사용자가 질문 8개에 답함                                 │
 │        ↓                                                  │
 │  답을 보고 유형을 정함 (T1? T12?)  ← AI 아님. 규칙표      │
 │        ↓                                                  │
 │  위험한 유형이면 → 여기서 멈춤. 문서 안 만듦              │
 │        ↓                                                  │
 │  안전하면 → 그 유형의 자료 덩어리를 창고에서 꺼냄         │
 │        ↓                                                  │
 │  [자료 덩어리] + [이 사람 사정] 을 AI에게 줌              │
 │        ↓                                                  │
 │  소명서 초안이 나옴                                       │
 │                                                           │
 └───────────────────────────────────────────────────────────┘
```

## 3. AI를 딱 두 군데서만 씁니다

이게 이 설계에서 제일 중요한 결정입니다.

| 하는 일 | 누가 | 왜 |
|---|---|---|
| 사용자가 쓴 긴 글에서 정보 뽑기 | **AI** | 문장에서 뜻을 읽는 건 규칙으로 못 함 |
| **유형 정하기** | **규칙표** | ← 여기가 핵심 |
| 자료 꺼내기 | 그냥 창고에서 꺼냄 | 유형이 16개뿐이라 찾을 게 없음 |
| **소명서 문장 쓰기** | **AI** | 글쓰기는 AI가 잘함 |
| 위험한 경우 걸러내기 | **규칙표** | 절대 AI에게 맡기면 안 됨 |

### 왜 유형 정하기를 AI에게 안 맡기나

AI는 **같은 질문에 매번 조금씩 다르게 답합니다.** 그런데 유형을 잘못 고르면 이런 일이 생깁니다.

> 도박 사이트에서 돈을 환전받았다가 계좌가 묶인 사람이 있습니다.
> 이 사람에게 소명서를 만들어 주면, 그 문서가 **"저 도박했습니다"라는 자백서**가 됩니다.
> 도와주려다 처벌받게 만드는 겁니다.

그래서 이 판단은 **표로 정해 놓습니다.** "3번 질문에서 '환전받은 돈'을 고르면 무조건 T12, 무조건 중단." 매번 똑같이 작동하고, 틀리면 어디가 틀렸는지 바로 찾을 수 있습니다.

## 4. 단계별로 뭘 하나

### 1단계 · 표 만들기 (스키마) ✅ 끝남

DB에 표 15개를 만들었습니다. 그중 제가 새로 만든 게 7개입니다.

| 표 이름 | 뭐가 들어가나 |
|---|---|
| `case_types` | 유형 16가지 목록 (T1~T16) |
| `questions` | 화면에 뜰 질문 9개 |
| `question_options` | 그 질문의 선택지 44개 |
| `type_rules` | "이렇게 답하면 이 유형" 규칙 20개 |
| `case_digests` | 실제 사례 요약 — **15행 (T1·T4·T12)** |
| `refusal_reasons` | 거절당한 이유 모음 ← **아직 비어 있음** |
| `snippet_packs` | 유형별로 합쳐 둔 자료 덩어리 — **3건 (T1·T4·T12)** |

### 2단계 · 기본 자료 넣기 (시드) ✅ 끝남

유형 16개, 질문 9개, 선택지 44개, 규칙 20개를 넣었습니다.
**이건 새로 쓴 게 아니라** 이미 만들어 둔 조사 문서에서 옮겨 담은 겁니다.

### 3단계 · 은행 20곳 조사 ✅ 끝남 (9/2)

은행마다 "이의제기할 때 뭘 가져오라"는 안내가 다릅니다. 이걸 모아 둔 곳이 국내에 없어서, **이게 우리 서비스의 유일한 차별점**입니다.

**새로 조사하지 않았습니다.** `기획자료/`에 20개사 전수 크롤링 자료(2026-08-29 · 출처 URL 포함)가 이미 있어서 그대로 옮겨 담았습니다 — `banks` 20행 · `bank_requirements` 14행.

**나온 결과가 중요합니다.** 요구 서류를 실제로 공개하는 곳은 **20곳 중 5곳뿐**입니다(카카오·씨티·전북·하나·케이뱅크). 나머지 15곳은 미공개라, 법에서 정한 필수 2종으로 대신 안내해야 합니다.

**중요한 규칙 하나** — 안 알려주는 은행은 **"안 알려줌"이라고 정직하게** 적습니다(`discloses_documents = false`). 추측해서 채우면 안 됩니다. 틀린 서류를 안내하면 그게 제일 큰 사고입니다.

### 4단계 · 사례 요약 쓰기 🔶 3개 유형 끝남 · 13개 남음

모은 실제 사례를 유형별로 정리합니다. 사례 하나당 **5칸**을 채웁니다.

| 칸 | 뭘 쓰나 |
|---|---|
| 상황 | 어떤 일이 있었나 |
| 쟁점 | 뭐가 문제였나 |
| **인정된것** | 뭐가 받아들여졌나 |
| **기각된것** | 뭐가 거절당했나 ← **제일 중요** |
| 표현 | 실제로 통했던 말투 |

**왜 '기각된것'이 제일 중요하냐면**, 실제로 이런 일이 있었습니다.

> 거래 금액이 2,104만 원이었는데 2,109만 원을 돌려달라고 청구했습니다.
> **5만 원 더 적었다는 이유로 그 부분이 거절되고, 소송비용까지 일부 물었습니다.**

이런 건 성공 사례 100건보다 값집니다. AI에게 "이렇게 쓰면 안 된다"고 알려 주는 자료가 되니까요.

**먼저 3개 유형만** 합니다 — T1(중고 물건), T4(게임 아이템), T12(도박 환전).
T12를 넣는 이유는 **차단이 진짜로 되는지 확인하려고**입니다.

9/3에 이 세 유형을 끝냈습니다 — 원문 7건 → 요약 15행(3유형 × 5칸) → 자료 덩어리 3건.
나머지 13개 유형은 **5단계 시험을 통과한 뒤** 같은 틀로 채웁니다. 순서를 바꾸면 안 됩니다.

### 5단계 · GPT로 시험해 보기 ✅ 끝남 (9/6)

DB랑 서비스를 연결하기 **전에**, 혼자 손으로 확인합니다.

1. 4단계에서 쓴 요약을 이어 붙여 한 덩어리로 만듭니다 (`pack/`에 3건 준비됨)
2. 그걸 가짜 사연과 함께 AI에게 줍니다 (`mock/사연/`에 3건 준비됨)
3. 나온 소명서를 5가지로 채점합니다 (`mock/채점표.md`)

| 확인할 것 | 이러면 실패 |
|---|---|
| 지어내기 | 내가 안 준 날짜·금액·이름이 문장에 나옴 |
| 법 조항 | 조항 번호를 틀리게 씀 |
| 실수 반복 | '기각된것'에 적어 둔 걸 그대로 씀 |
| 출처 | 어느 자료를 보고 썼는지 못 밝힘 |
| **도박 차단** | **도박 사연을 줬는데 소명서를 만들어 줌** |

**마지막 항목에서 실패하면 그 자료 덩어리는 버리고 다시 씁니다.**

**9/6에 돌렸고 5개 항목을 전부 통과했습니다.** 특히 도박 사연(T12)에 소명서가 나오지 않았습니다.
두 번 돌려서 두 번 다 막힌 것까지 확인했습니다.

한 번 돌리는 데 **약 $0.08**이 듭니다(3유형 기준). 결과는 `mock/결과/`에 쌓입니다.
자세한 건 [인수인계.md](인수인계.md) 3-2·4장.

이렇게 미리 확인하는 이유는, 형식을 잘못 정해 놓고 16개 유형을 다 채운 다음에 갈아엎는 게 제일 손해이기 때문입니다.

### 6단계 · 백엔드에 넘기기 ⬜

시험을 통과하면 서버 담당자에게 **세 가지만** 넘깁니다.

- 유형별 자료 덩어리 (`snippet_packs`)
- 유형 판정 규칙 (`type_rules`)
- 은행·증거 자료

**서버 담당자는 이걸 꺼내서 AI에게 전달하기만 합니다.**
그래서 제가 나중에 문장을 고쳐도 **서버 코드는 안 건드려도 됩니다.** 마감 직전에 문구는 반드시 고쳐지는데, 그때 이 구조가 큽니다.

## 5. 화면 선택지도 제가 만듭니다

이유가 있습니다. 선택지 하나하나에 **속으로 붙은 이름표**가 있습니다.

```
화면에 보이는 글자 :  "환전받은 돈입니다"
속에 붙은 이름표   :  exchange
                          ↓
규칙표가 읽는 것   :  exchange → T12 → 중단
```

화면 담당자가 이름표를 마음대로 `환전`이나 `exch`로 바꾸면, **규칙표가 못 알아듣고 조용히 그냥 넘어갑니다.** 막아야 할 사람에게 소명서가 나가는 사고가 이렇게 납니다.

그래서 **글자도 이름표도 제가 DB에 넣고, 화면은 그걸 받아서 보여 주기만** 합니다.
덤으로 **글자를 고칠 때 앱을 다시 배포할 필요가 없습니다.** DB에서 한 줄 고치면 화면이 바뀝니다.


내 컴퓨터에서 SQL 파일 한 번에 실행하기:
```bash

  "psql -h 127.0.0.1 -p 15432 -U pullim -d pullim" < sql/파일이름.sql
```
