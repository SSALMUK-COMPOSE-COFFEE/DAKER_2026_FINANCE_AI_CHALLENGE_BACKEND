# 백엔드 패치 안내 — C축에서 B축으로

작성 2026-09-06 · 김주현

백엔드 레포는 다른 사람 것이라 직접 푸시하지 않았습니다. 패치 4개로 만들어 뒀습니다.
**기존 API를 갈아엎지 않습니다.** 코드 추가가 대부분이고 기존 동작은 그대로 둡니다.

## 적용

레포 루트에서 순서대로.

```bash
git apply --3way 백엔드_리스크게이트.patch
git apply --3way 백엔드_팩연결.patch
git apply --3way 백엔드_db_init_003.patch
git apply --3way 백엔드_은행숫자.patch
```

> `--3way` 를 꼭 붙이세요. 패치는 LF 인데 Windows 작업본은 CRLF 라
> 그냥 `git apply` 하면 "patch does not apply" 가 납니다.

## 패치 4개

| 패치 | 무엇 | 규모 |
|---|---|---|
| **리스크게이트** | 위험 유형을 LLM 호출 **전에** 막는다 | +139 / -0 |
| **팩연결** | 유형별 근거 자료를 프롬프트에 넣는다 | +129 / -4 |
| **db_init_003** | `docker compose down -v` 후에도 콘텐츠 계층이 살아남게 | +1,336 / -0 |
| **은행숫자** | 공개 은행 수 4곳 → 5곳 정정 | +2 / -2 |

## 1. 리스크게이트 — 가장 급합니다

**지금 배포본은 도박 환전 사연에도 소명서를 만들어 줍니다.** 그 문서는 은행에 내는
순간 "저 도박했습니다"라는 자백서가 됩니다.

`intake.py` 의 q2 선택지에 `환전대리송금` 이 있지만, 그 값을 읽어서 막는 코드가
어디에도 없습니다. `generate_draft()` 가 게이트 없이 바로 템플릿을 채우고 LLM 을 부릅니다.

- `app/services/riskgate.py` 신규 — `question_options.stop_here` 를 읽는다
- 차단 조건과 안내 문구가 **DB 에 있습니다.** 문구를 고칠 때 백엔드 배포가 안 걸립니다
- 캐시 5분. 요청마다 DB 를 때리지 않습니다
- **DB 를 못 읽으면 막습니다(fail closed).** 통과시키면 사고이기 때문입니다.
  시드 7건을 안전망으로 두고 그 경로로 돌면 WARNING 로그가 남습니다
- `/documents/rewrite` 도 같이 막았습니다. 안 막으면 초안 게이트를 우회하는 길이 됩니다
- `DocumentDraftResponse.blocked` 필드 추가(기본 `false`) — 기존 화면은 안 고쳐도 됩니다

### 화면 쪽에서 해 주셔야 하는 것

DB 에는 **중단 선택지가 7개**인데 지금 문진으로는 **1개만** 들어옵니다.

| DB 의 중단 선택지 | 지금 받을 수 있나 |
|---|---|
| `q3.exchange` 환전받은 돈 | 예 (`q2=환전대리송금` 으로) |
| `q3.proxy` 부탁받고 다시 송금 | 아니오 |
| `q6f.sent` 돌려달라 해서 이미 보냄 | 아니오 |
| `q8.gambling` 도박·토토 환전 | 아니오 |
| `q8.fx` 환치기 | 아니오 |
| `q8.access_medium` 통장·카드 넘김 | 아니오 |
| `q8.proxy_withdraw` 대신 인출·송금 | 아니오 |

문항 두 개가 없어서입니다.

- **`q8`** — "다음 중 해당하는 것이 있나요?" 복수선택. 중단 선택지 4개가 전부 여기 있습니다
- **`q6f`** — "상대가 그 돈을 돌려달라고 하던가요?" (q6 후속)

둘을 추가하면 7개가 다 걸립니다. 선택지 문구와 값은 `question_options` 에 이미
들어 있으니 그대로 내려받아 쓰시면 됩니다.

## 2. 팩연결 — 근거 없는 문장을 줄입니다

지금 프롬프트에는 **이 유형에서 실제로 무엇이 인정되고 무엇이 기각됐는지가 없습니다.**
그래서 모델이 그럴듯하지만 근거 없는 문장을 씁니다.

`_generate()` 의 사용자 블록에 `<<<case_pack>>>` 하나를 더합니다.

```python
pack = await load_case_pack(req.answers)
user = "\n\n".join([
    user_block("facts", ...),
    *([user_block("case_pack", pack["pack_text"])] if pack else []),   # ← 추가
    user_block("evidence", ...),
    user_block("citations", ...),
    user_block("memo", ...),
    user_block("template_reference", ...),
])
```

시스템 프롬프트에 규칙 한 줄이 붙습니다 — *"`<<<case_pack>>>` 의 '기각된 것'에 적힌
서술은 반복하지 않는다. 거기 실린 법조문 외의 조항은 인용하지 않는다."*

### 팩 안에 들어 있는 것

유형별로 사례 요약 5칸(상황 / 쟁점 / 인정된 것 / 기각된 것 / 실제로 통한 표현)과
**법조문 전문**이 들어갑니다. 범위 안 유형은 법 제7조(이의제기 근거), 차단 유형은
제16조(벌칙)입니다. `다툴 조항`(제7조 제1항 몇 호로 다투는지)도 함께 나갑니다.

### 유형 판정 — 코드에 유형 목록을 박지 않았습니다

문진 답에서 **두 축만** 뽑아 `case_types` 에서 찾습니다.

| 축 | 어디서 나오나 |
|---|---|
| 구조 | `q2=환전대리송금` → 환전대리 · `q5=더받음` → 계좌경유 · 목적물 없음 → 계좌경유 · 그 외 물건넘김 |
| 목적물 | `q3` 값 그대로 (`금귀금속외화` → `금외화` 만 다름) |

유형이 늘거나 이름이 바뀌어도 백엔드는 그대로입니다. 서버 DB 로 검증한 결과입니다.

| 문진 답 | 판정 | 팩 |
|---|---|---|
| 판매대금 + 실물중고 | T1 | 2,211자 |
| 판매대금 + 금귀금속외화 | T2 | 3,148자 |
| 판매대금 + 암호화폐 | T3 | 2,807자 |
| 판매대금 + 게임재화 | T4 | 2,334자 |
| 판매대금 + 실물중고 + 더받음 | T8 | 2,896자 |
| 이유모름 + 없음 | T9 | 3,093자 |
| 환전대리송금 + 없음 | T12 | 1,693자 |
| 환전대리송금 + 금귀금속외화 | T13 | 1,963자 |
| 판매대금 + 상품권·팬덤굿즈·용역 | (팩 없음) | 기존 템플릿 경로 |

**팩이 없으면 그냥 넘어갑니다.** 소명서는 기존대로 나오고 근거만 얇아집니다.
차단은 여기가 아니라 리스크게이트가 합니다.

## 3. db_init_003 — 조용한 시한폭탄

`db/init/` 에 `001`·`002` 밖에 없습니다. `003`(콘텐츠·판정 계층)과 시드가 없어서
**`docker compose down -v` 한 번에 문진 선택지·판정 규칙·사례 요약·프롬프트 팩이
전부 사라지고 빈 스키마만 남습니다.** `db/README.md` 가 스키마를 고쳤으면 그렇게
하라고 안내하고 있어서 실제로 일어날 수 있습니다.

빈 `type_rules` 로 API 가 뜨면 막아야 할 사람을 막지 못합니다.

`003` + 시드 8개를 넣고 `db/README.md` 에 번호 규칙을 적었습니다.
점검 쿼리(`900_check.sql`)는 기동 때 돌 이유가 없어 뺐습니다.

## 4. 은행숫자

조사 결과 요구 서류를 사용자에게 보여줄 수 있는 곳은 **5곳(25%)** 입니다.
안내문에 열거한 3곳(카카오·씨티·전북)과, 안내문은 없지만 배포 중인 법정서식에
첨부서류가 적혀 있는 2곳(하나·케이뱅크)입니다.

`BANK_DISCLOSURE_NOTE` 의 4곳(20%)을 5곳(25%)으로 고칩니다.
