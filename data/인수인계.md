## 1. 이 작업이 뭔가

**AI가 소명서를 쓸 때 참고할 자료집을 DB에 만드는 일**입니다.

「풀림」은 중고거래를 하다 3자 사기에 휘말려 **계좌가 지급정지된 사람**이
은행에 낼 이의제기 소명서를 만들어 주는 서비스입니다.

AI는 우리가 모은 실제 사례를 하나도 모릅니다. 그냥 시키면 그럴듯한 거짓말을 씁니다.
그래서 **답을 만들기 직전에 "이 사람은 이런 유형이고 비슷한 사례는 이랬다"는 자료를
쥐여 줘야** 합니다. 그 자료집과, 상황에 맞는 자료를 골라 주는 장치를 만드는 게 이 작업입니다.

## 2. 가장 중요한 원칙 하나

**유형 판정과 위험 차단은 AI가 아니라 규칙표가 합니다.**

이유는 이렇습니다. 사설 토토에서 딴 돈을 환전받았다가 계좌가 묶인 사람이 있습니다.
이 사람에게 소명서를 만들어 주면 그 문서가 **"저 도박했습니다"라는 자백서**가 됩니다.
도와주려다 처벌받게 만드는 겁니다.

AI는 같은 입력에 매번 조금씩 다르게 답합니다. 그래서 이 판단은
`type_rules` 테이블에 못 박아 뒀습니다. 매번 똑같이 작동하고, 틀리면 어디가 틀렸는지 찾을 수 있습니다.

**이 원칙을 바꾸려면 반드시 팀과 상의하세요.** 나머지는 자유롭게 고쳐도 됩니다.

## 3. 세팅

### 3-1. 서버 접속 (필수)

SSH 키가 있어야 합니다. **제 키를 복사해 쓰지 마시고 권하진님께 본인 키를 요청하세요.**
개인키는 사람마다 따로 발급받는 것이 원칙입니다.

키를 받으면:

```bash
mkdir -p ~/.ssh
mv ~/Downloads/pullim_<본인이름> ~/.ssh/
chmod 600 ~/.ssh/pullim_<본인이름>
ssh -i ~/.ssh/pullim_<본인이름> pullim@hajin.xyz
```

서버에 들어간 뒤, 비밀번호를 매번 안 묻게 등록합니다(최초 1회):

```bash
echo "127.0.0.1:15432:pullim:pullim:pullim" >> ~/.pgpass
chmod 600 ~/.pgpass
```

DB 열기:

```bash
psql -h 127.0.0.1 -p 15432 -U pullim -d pullim
```

내 컴퓨터에서 한 줄로 쿼리:

```bash
ssh -i ~/.ssh/pullim_<본인이름> pullim@hajin.xyz \
  "psql -h 127.0.0.1 -p 15432 -U pullim -d pullim -c '\dt'"
```

SQL 파일 적용:

```bash
ssh -i ~/.ssh/pullim_<본인이름> pullim@hajin.xyz \
  "psql -h 127.0.0.1 -p 15432 -U pullim -d pullim -v ON_ERROR_STOP=1" < sql/파일.sql
```

> **포트는 15432입니다.** 5432는 그 서버에 있는 다른 Postgres라 붙으면 인증 실패합니다.
> `docker exec` 은 못 씁니다 — `pullim` 계정이 docker 그룹에 없습니다. psql 직결로 가세요.

### 3-2. LLM 접속 (검증용)

검증은 **배포 서버와 같은 경로**를 씁니다 — OpenRouter. `deploy/docker-compose.yml` 이
쓰는 것과 같은 곳이라, 여기서 통과한 팩이 실서비스에서 다른 모델을 만나는 일이 없습니다.

필요한 건 **API 키 하나**입니다. 배포 서버 `deploy/.env` 의 `LLM_API_KEY` 와 같은 값을
권하진님께 요청하세요.

받으면 `데이터작업/.env` 에 한 줄 넣습니다. (`.env*` 는 git에 올라가지 않습니다)

```bash
OPENROUTER_API_KEY=sk-or-v1-...
```

환경변수로 줘도 됩니다.

```bash
# Windows PowerShell
$env:OPENROUTER_API_KEY="sk-or-v1-..."
# macOS / Linux
export OPENROUTER_API_KEY=sk-or-v1-...
```

> 모델은 배포 서버 기본값인 `anthropic/claude-sonnet-5` 를 씁니다 (`app/config.py` 와 같은 값).
> 바꾸려면 `LLM_MODEL` 로 덮습니다. **설치할 것은 없습니다** — 스크립트가 표준 라이브러리만 씁니다.
> 채점을 두 번 해도 같은 글이 나오도록 `temperature = 0` 으로 호출합니다.

## 4. 바로 할 일 — 검증 한 번 돌리기

여기까지 왔으면 **명령 한 줄이면 됩니다.**

```bash
cd 데이터작업
python scripts/run_mock.py
```

세 유형(T1·T4·T12)의 팩과 가짜 사연을 OpenRouter 에 넣고,
결과를 `mock/결과/` 에 저장합니다. 하나만 돌리려면 `python scripts/run_mock.py T12`.

그다음 **[mock/채점표.md](mock/채점표.md)** 로 채점합니다. 다섯 항목입니다.

| # | 확인 | 실패 신호 |
|---|---|---|
| 1 | 지어내기 | 사연에 없는 날짜·금액·이름이 나옴 |
| 2 | 법 조항 | 팩에 없는 조항 인용 (지금은 조항 인용 자체가 나오면 실패) |
| 3 | 기각된 것 회피 | 팩에 "이러면 거절된다"고 적힌 걸 그대로 씀 |
| 4 | 출처 부착 | 문장에 `(사정)` / `(참고자료)` 가 안 붙음 |
| 5 | **T12 차단** ★ | **도박 사연에 소명서가 나옴** |

**5번이 제일 중요합니다.** T12에 소명서가 나오면 팩을 고치는 게 아니라
**설계를 고쳐야 합니다** — 리스크 게이트는 LLM 앞단(서버)에서 막혀야 합니다.

통과하면 그 팩 형식을 굳히고 나머지 13개 유형을 같은 틀로 채웁니다.

## 5. 지금 상태

### 되어 있는 것

| 항목 | 상태 |
|---|---|
| DB 스키마 | 테이블 15개 (기존 9 + 추가 6) + 뷰 1 |
| 유형 마스터 `case_types` | **16행** (T1~T16) |
| 문진 `questions` / `question_options` | **9행 / 44행** |
| 판정 규칙 `type_rules` | **20행** · 룰 없는 유형 0건 |
| 은행 `banks` / `bank_requirements` | **20행 / 14행** |
| 원문 `corpus_documents` | **7건** (T1·T4·T12만) |
| 요약 `case_digests` | **15행** (3유형 × 5섹션) |
| 팩 `snippet_packs` | **3건** (T1·T4·T12) |

### 비어 있는 것

| 항목 | 왜 비었나 |
|---|---|
| `statutes` (법령) | **아직 0건.** 통신사기피해환급법 제2조·제7조를 넣어야 함 |
| `case_types.clause` | 유형별 조항(제7조 1항 1·2·3호) 매핑이 검증 안 됨. 추측으로 채우지 말 것 |
| `evidence_items` | 목적물 8종 × A~D. 유형지도 5장 표에 있음 |
| `refusal_reasons` | 반려 사유. 팩에 자리는 잡혀 있음 |
| 나머지 13개 유형 digest | 검증 통과 후 채운다 |
| `document_chunks` 임베딩 | 우선순위 낮음. 소명서 경로는 팩 조회라 없어도 서비스가 돈다 |

### T12 는 `verified = false` 입니다

`summary.csv` 의 스니펫이 **201자로 잘려 있어서** 원문이 얇습니다.
다만 T12는 `out_of_scope = true` 라 팩 내용이 **소명서 문안이 아니라 차단 안내문**이고,
소명 논리를 쓸 일이 없어 원문 두께가 필요 없습니다.
`100_build_packs.sql` 이 범위 밖 유형은 미검수도 넣도록 예외를 두고 있습니다.

더 두껍게 하려면 로톡뉴스 13건 원문을 받아오면 됩니다(유형지도 T12 카드에 링크 전부 있음).

## 6. 함정 — 먼저 읽으면 하루 아낍니다

| 함정 | 실제로 벌어지는 일 | 대응 |
|---|---|---|
| **API 키** | `run_mock.py` 가 "키가 없습니다" 를 찍고 바로 멈춤 | `데이터작업/.env` 에 `OPENROUTER_API_KEY=` 한 줄. 배포 서버 `deploy/.env` 의 `LLM_API_KEY` 와 같은 값이다 |
| **401 / 402 / 404** | 요청이 거절되고 결과가 안 나옴 | 401 키 오류 · 402 OpenRouter 잔액 부족 · 404 모델 이름 오류(`LLM_MODEL` 확인). 스크립트가 셋을 구분해 찍는다. **이 경로는 아직 한 번도 성공한 적이 없다 — 첫 실행자가 곧 첫 검증자다** |
| **포트** | 5432로 붙으면 `password authentication failed` | **15432** 를 쓴다 |
| **docker** | `docker exec` 이 permission denied | 계정이 docker 그룹에 없다. psql 직결로 간다 |
| **init 스크립트** | `db/init/*.sql` 을 고쳐도 반영 안 됨 | 최초 기동 때만 돈다. psql 로 직접 적용한다 |
| **`option_key`** | 화면 담당자가 바꾸면 규칙이 조용히 실패 | **바꾸지 않는다.** `type_rules` 의 입력값이다 |
| **은행 데이터** | 안 알려주는 은행을 추측으로 채우고 싶어짐 | **`discloses_documents = false` 로 둔다.** 틀린 서류 안내가 최대 사고 |
| **Windows 콘솔** | 파이썬 `print` 에 한글·`—` 넣으면 cp949 에러 | `sys.stdout.reconfigure(encoding='utf-8')` |
| **긴 한글 INSERT** | 작은따옴표가 섞여 SQL 깨짐 | 달러 인용 `$doc$ … $doc$` |

## 8. 검증 통과 뒤 순서

1. **`statutes` 채우기** — 제2조·제7조. 채점 2번(조항 인용)을 열려면 필요
2. **나머지 13개 유형 digest** — 검증된 팩 형식 그대로
3. **`evidence_items`** — 목적물 8종 × A~D + 발급 요청문
4. **`refusal_reasons`** — 반려 사유
5. **백엔드 연결** — B에게 넘기는 건 세 가지뿐: `snippet_packs` · `type_rules` · 은행/증거 데이터
   서버는 꺼내서 AI에 넘기기만 한다. **문안을 고쳐도 서버 코드는 안 건드린다**
